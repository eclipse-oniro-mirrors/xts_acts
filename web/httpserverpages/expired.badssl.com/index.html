SSL Error Explanation

What is a Certificate Expiration Error?

When you visit a website secured with HTTPS, your browser verifies the SSL/TLS certificate presented by the server. One of the critical checks is whether the certificate is still within its validity period. Every certificate has a Not Before and Not After date. If the current time falls outside this window, the certificate is considered expired.

The error ERR_CERT_DATE_INVALID indicates that the certificate's validity period has ended. This is one of the most common SSL errors encountered on the web, affecting millions of websites each year when administrators forget to renew their certificates.

Why Do Certificates Expire?

Certificates have expiration dates as a security measure. This limits the damage if a private key is compromised, ensures organizations regularly re-validate their identity, and encourages the use of up-to-date cryptographic algorithms. Modern best practices recommend certificates with lifetimes of 90 days or less, with automated renewal via ACME protocols like Let's Encrypt.

Common Error Codes

Across different platforms, expired certificate errors may appear as:

  • ERR_CERT_DATE_INVALID (Chrome/Chromium)
  • SEC_ERROR_EXPIRED_CERTIFICATE (Firefox)
  • CERT_DATE_INVALID (Edge/Internet Explorer)
  • NSURLErrorServerCertificateUntrusted (iOS/macOS)
  • SSL_ERROR_EXPIRED_CERT_ALERT (OpenSSL)

Related Error Types

The following SSL/TLS errors are related to certificate validation failures:

  • ERR_CERT_AUTHORITY_INVALID — The certificate is signed by an untrusted certificate authority.
  • ERR_CERT_COMMON_NAME_INVALID — The certificate hostname does not match the requested domain.
  • ERR_CERT_DATE_INVALID — The certificate has expired or is not yet valid.
  • ERR_CERT_REVOKED — The certificate has been revoked by the issuing authority.
  • ERR_CERT_PINNED_KEY_NOT_IN_CERT_CHAIN — The certificate does not match the expected public key pin.
  • ERR_CERT_WEAK_SIGNATURE_ALGORITHM — The certificate uses a weak or deprecated signature algorithm.
  • ERR_SSL_PROTOCOL_ERROR — The TLS protocol version negotiation failed.
  • ERR_SSL_VERSION_OR_CIPHER_MISMATCH — No common TLS version or cipher suite exists.
  • ERR_CERT_NO_REVOCATION_MECHANISM — The certificate has no OCSP or CRL endpoint.
  • ERR_CERT_UNABLE_TO_CHECK_REVOCATION — Unable to verify the certificate revocation status.

Troubleshooting Guide

1. Verify System Clock
An incorrect system clock is the most common cause of false expiration errors. Ensure your device's date and time are set correctly. Enable automatic time synchronization (NTP) to prevent drift.
2. Clear Browser Cache and Certificates
Cached certificates or intermediate CA certificates may cause validation issues. Clear your browser cache and the local certificate store. In Chrome, navigate to chrome://settings/certificates to manage stored certificates.
3. Check for Intermediates
Missing intermediate certificates can cause chain validation failures. Ensure the server presents the full certificate chain. Use tools like SSL Labs (ssllabs.com) to verify the chain is complete.
4. Inspect with OpenSSL
Use openssl s_client -connect expired.badssl.com:443 -showcerts to inspect the certificate chain. Check the notAfter field to confirm expiration dates.
5. Disable Antivirus/Proxy Interference
Some antivirus software and corporate proxies perform SSL interception, which can replace or modify certificates. Temporarily disable these to check if they are causing the issue.

Fix Suggestions

For Website Administrators

1
Renew the Certificate — Contact your certificate authority or use an automated tool like certbot (Let's Encrypt) to obtain a new certificate. Most CAs send expiration reminders 30, 14, and 7 days before expiry.
2
Install the New Certificate — Replace the expired certificate on your web server. Ensure you install both the leaf certificate and any intermediate certificates in the correct order.
3
Set Up Automated Renewal — Use ACME clients like certbot, acme.sh, or Caddy's built-in certificate management to automate renewal. Configure a cron job or systemd timer to run renewal checks weekly.
4
Monitor Expiration — Set up monitoring tools (Nagios, Datadog, UptimeRobot) to alert you before certificates expire. Use the openssl x509 -checkend 2592000 command to check if a cert expires within 30 days.
5
Use Certificate Transparency — Subscribe to CT log monitoring to detect unauthorized certificates and track your domain's certificate issuance. Google's Certificate Transparency logs provide public visibility into all issued certificates.

For Developers Testing SSL Errors

1
Handle Errors Gracefully — Catch SSL errors in your application and display user-friendly messages. Never silently ignore certificate errors in production code.
2
Implement Certificate Pinning Carefully — When using certificate pinning, ensure you have a backup pin and a mechanism to update pins without requiring an app update.
3
Test with Real-World Scenarios — Use badssl.com test domains to verify your application handles various SSL errors. Test with this expired. certificate page and other error scenarios.

FAQ

Q: Can I still access a website with an expired certificate?

Technically yes, by manually bypassing the browser warning, but this is highly discouraged. The expired certificate means the connection cannot be verified as secure. Sensitive data transmitted may be intercepted.

Q: How long are SSL certificates valid?

As of September 2020, publicly trusted certificates can have a maximum validity of 398 days (approximately 13 months). Apple, Google, and Mozilla have further reduced this to 397 days. Industry best practice recommends 90-day certificates with automated renewal.

Q: What happens if I ignore the expiration warning?

Your browser will establish the connection, but the security guarantees of TLS are compromised. You cannot verify the server's identity, making you vulnerable to man-in-the-middle attacks. The encryption itself may still work, but authentication fails.

Q: Does an expired certificate mean the website is hacked?

Not necessarily. An expired certificate usually indicates administrative oversight rather than a security breach. However, you should be cautious as attackers could exploit the expired certificate window.

Q: Can expired certificates be renewed?

Certificates cannot be renewed in-place. You must obtain a new certificate from the CA. The term "renewal" typically refers to re-issuing a certificate with the same or similar parameters, often with the same private key or a newly generated one.

Q: How does HSTS interact with expired certificates?

If HSTS (HTTP Strict Transport Security) is enabled and the certificate expires, users may be completely unable to access the site since HSTS prevents fallback to HTTP. This is why automated renewal is critical for HSTS-enabled sites.
